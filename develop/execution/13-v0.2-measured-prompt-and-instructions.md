# 13. v0.2.0 — Claude's own prompt, instruction discovery, speed

2026-10-16. Covers BACKLOG P0-6, P0-7, and P0-8 (`research/05`). Each change was written test first.

## P0-6 Claude's own prompt, measured

Claude Code 2.1.300+ writes an `api-request-shape` row per request to the transcript. Confirmed on this machine (2.1.301) that the row holds `shape.system` (text blocks) and `shape.tools[]` (with `defer_loading` on placeholders). The same files hold `api-request-blob` rows that carry message content.

`src/claude-prompt.js` keeps sizes only. Lines are filtered on raw bytes for `"type":"api-request-shape"` before any decoding (`eachJsonLine` `lineFilter`), so blob lines are never parsed. A test checks that no prompt or tool text reaches the summary.

Live result (workspace `seungdo-skills`, confirmed):

| part | tokens |
|---|---|
| system | 3,185 |
| 13 built-in tools | 16,781 |
| MCP | 537 |
| deferred list | 403 |
| **total** | **20,906** |

The observed start of that workspace is 34,438 and its setup is 9,819. The setup plus Claude's own prompt comes to 30,725. The remaining ~3.7k is the first message and anything unmeasured. The headline now says this instead of "the rest is built-in". In `details`, a new `agent` segment splits the gap out, and the menu bar gives it its own color.

## P0-7 instruction discovery

`src/instructions.js` follows each vendor's documented discovery. The docs were fetched 2026-10-16; the sources are in `docs/reference.md`.

- **Claude**: ancestor `CLAUDE.md` files, `CLAUDE.local.md`, `@imports` up to four hops, rules unless they have `paths`, and `AGENTS.md` when no `CLAUDE.md` exists.
- **Codex**: the `AGENTS.md` chain from the git root, capped at `project_doc_max_bytes`, plus fallback names.
- **Kiro**: steering marked `inclusion: always` or with no `inclusion`, plus `AGENTS.md`.

On this machine nothing changed for the two workspaces checked: neither has project instruction files. Only the global files apply, which is consistent.

Not modelled:
- `claudeMdExcludes`
- the Project instructions setting
- HTML comment stripping
- external-import approval
- `CODEX_HOME`

**Hypothesis**: when Codex hits the byte cap it truncates the last file rather than dropping it. The guide says "stops adding files". Check `codex-rs` `project_doc` to settle it.

## P0-8 speed and size

`audit` took 4.1 s. Profiling showed 2.4 s of that in `readdirSync`, all of it `countExcludedSkills` walking `~/.codex/.tmp/marketplaces`: 58,142 directories of staging checkouts and their `.git`. Changes:

- `.git` is never walked.
- The excluded-skill count skips `.tmp`, `sessions`, `projects`, `cache`, `logs`.
- `src/jsonl.js` reads logs line by line with a 1 MiB buffer. No log is held as one string, which also removes the ~512 MB V8 string limit.
- Baselines read only up to the first sample, of the newest 2×N files.
- History skips files untouched since the 7-day window opened.
- `Math.max(...samples)` became a `reduce`, so long sessions cannot overflow the stack.

| command | before | after |
|---|---|---|
| audit | 4.11 s | 0.94 s |
| details | 4.07 s | 0.96 s |
| history | 0.62 s | 0.41 s |

Numbers are identical before and after (headline 69,435 · 17,268 · 4.6%).

Menu bar: `ProcessRunner` drains stdout and stderr on separate threads, which fixes the 64 KB pipe deadlock. It also enforces a 60 s deadline, then terminate, then kill. Both `TelemetryLoader` and `CLIRunner` use it. Tested: a 400 KB stderr does not hang, and `sleep 30` is stopped at 1 s.

Claude telemetry now skips `isSidechain` rows, as history already did.

## v0.2.1 — drift

- The baseline now carries `drift`: the newest start against the median of the earlier ones. It is reported at ≥15% and ≥2,000 tokens (≥1 point for Kiro), and needs at least two earlier starts.
- Each session also carries its agent version: Claude row `version`, Codex `session_meta.cli_version`. A version change is shown only when it changed.
- Live check: workspace `seungdo-skills` shows `latest session started at 55,549 tokens, up from 46,145`. The version did not change, so none is shown.
- Skipped: the menu bar notification. The rise alone is not actionable yet. Add it once the cause can be pinned to an item, for example by diffing two `api-request-shape` rows.
- Not started: OpenCode. Reading `opencode.db` needs SQLite. `node:sqlite` is not in Node 20, our floor. The options are to raise the floor to 22.5, shell out to `sqlite3`, or add a dependency; this needs a decision from the owner. This machine has 7 OpenCode sessions, the last on 2026-03-26.
